# TUI 任务运行界面

Status: ready-for-agent

## Problem Statement

当前 TUI 只展示初始界面和输入编辑，Enter 不提交任务，也没有服务端连接。用户无法在终端跟踪任务的流式响应、工具调用和执行结果。长工具结果会占据大量空间，需要按工具名快速浏览调用摘要，并按需展开整个工具调用区的明细。

## Solution

参考运行界面截图，提供按时间组织的任务输出区和固定在底部的输入区、状态栏。输入后按 Enter 创建任务，或通过 `--task-id` 接入已有任务。文本实时追加；助手文本之间的连续工具调用组成工具调用区，收起时按工具名分组展示调用摘要，不预览结果。点击区域统一开关原地展开该区所有调用的完整参数和结果，再次操作可收起。所有文本统一左右各留两个终端字符，工具调用区与前后文本各隔一行空白。默认跟随输出，上翻暂停跟随，可点击“回到底部”恢复。

收到服务端新增的 `task_completed` 后显示任务完成，主动关闭订阅并允许提交下一项任务。连接断开、文本结束和模型请求完成均不能替代任务完成事件。

## User Stories

1. As a 终端用户, I want 输入需求后按 Enter 创建任务, so that 我能直接开始工作。
2. As a 终端用户, I want 空白输入不提交, so that 不会创建无效任务。
3. As a 终端用户, I want 通过任务 ID 接入已有任务, so that 能查看其历史和后续输出。
4. As a 终端用户, I want 看到自己提交的需求, so that 能理解输出对应的任务。
5. As a 终端用户, I want 文本随事件到达逐步显示, so that 不必等待完整响应。
6. As a 终端用户, I want 完整文本事件不重复已显示的流式响应, so that 阅读不被重复内容干扰。
7. As a 终端用户, I want 非流式任务也能显示完整响应, so that 两种服务配置均可使用。
8. As a 终端用户, I want 按工具名分组浏览调用摘要，并能展开完整参数, so that 知道正在执行什么操作。
9. As a 终端用户, I want 工具结果与对应调用放在一起, so that 能理解每次调用的结果。
10. As a 终端用户, I want 工具结果默认全部收起且没有预览行, so that 长输出不会淹没其他内容。
11. As a 终端用户, I want 收起时仍能看到执行中和失败标记, so that 无需展开即可发现未完成或异常调用。
12. As a 终端用户, I want 一次点击展开整个工具调用区的全部调用明细并能再次收起, so that 能在摘要和详情之间切换。
13. As a 终端用户, I want 展开历史结果时保持阅读位置, so that 不会跳回最新输出。
14. As a 终端用户, I want 新输出默认自动滚动到底部, so that 始终看到最新进展。
15. As a 终端用户, I want 上翻后暂停自动跟随, so that 能安心阅读历史。
16. As a 终端用户, I want 点击“回到底部”恢复跟随, so that 能迅速返回实时输出。
17. As a 终端用户, I want 拖选和复制输出文本, so that 能保存或分享执行信息。
18. As a 终端用户, I want 点击展开与拖选互不干扰, so that 不会误触操作。
19. As a 终端用户, I want 调整终端宽度后按扣除左右留白的宽度正确折行并保留区域展开状态, so that 窄屏仍可阅读。
20. As a 终端用户, I want 运行时继续编辑下一条输入但不重复提交, so that 能提前准备后续任务。
21. As a 终端用户, I want 收到整体完成事件后看到完成状态并能再次提交, so that 明确知道何时可以开始下一项工作。
22. As a 终端用户, I want 看到工具错误和连接错误, so that 能区分执行问题与网络问题。
23. As a 终端用户, I want 连接恢复时续传而不重复已有输出, so that 阅读记录保持连贯。
24. As a 终端用户, I want 未收到整体完成通知时不显示成功, so that 不会被误导。
25. As a 终端用户, I want 退出时释放网络连接并恢复终端, so that 程序正常结束。
26. As a 终端用户, I want 所有文本与左右边界保持留白，工具调用区与助手文本之间有空行, so that 界面更易阅读。

## Implementation Decisions

- 扩展现有 Bubble Tea 模型、输出渲染和鼠标交互；保留输入编辑、文本复制、退出及终端尺寸适配行为。网络请求异步执行，不阻塞界面事件循环。
- 分离任务服务对接、任务输出状态和界面渲染职责；优先沿用现有模型边界，遵守 SOLID，关键协议处理与交互规则添加注释。
- 默认对接 `http://localhost:8080`；任务 ID 来自创建响应或 `--task-id`，不硬编码示例任务。
- 创建接口为 `POST /tasks`，请求包含字符串 `input`，成功为 HTTP 201 和 `task_id`。创建失败显示错误、保留可重试输入；不要自动重发可能已入队的创建请求。
- 订阅接口为 `GET /tasks/{task_id}/events`。先解析 SSE，再解析外层 `ID`、`Type`、`Delta`，最后解析作为 JSON 字符串的 `Delta`。
- 处理完成后记录事件 ID；断线续传使用 `Last-Event-ID`，按事件 ID 防止重复应用。断线提示连接问题，不将其等同于任务失败或成功；退出或收到完成事件后停止订阅及重连。
- `text_delta` 增量显示；`text` 是完整响应，不可无条件再次追加。无 delta 时显示完整文本，有对应增量时合并为单份响应；不同响应轮次不得互相覆盖。协议没有响应关联 ID，需用真实回放验证合并行为，不能仅按全文相等删除合法的后续响应。
- `tool_call` 使用 `name`、`call_id`、`arguments`；工具结果和错误通过 `call_id` 归入对应调用，迟到或交错结果仍归属原调用及其工具调用区，不移动到当前区。
- 助手文本之间的连续工具调用组成一个工具调用区；任务开头、结尾也可有工具调用区，不跨助手文本或任务边界合并。`text_delta` 与对应完整 `text` 仍遵循单份响应合并规则，不因重复完整文本制造额外区域。
- 收起时按工具名分组，每个工具分组一条逻辑行，长行自动折行。工具名按区内首次出现排序，同名调用的摘要保持调用顺序。例如 `read_file a.txt → list_dir . → read_file b.py` 展示为 `read_file a.txt, b.py` 换行 `list_dir .`。
- 调用摘要按工具类型提取：目录和文件工具展示路径，命令工具展示命令，搜索工具展示搜索词；未知工具展示紧凑参数，无法解析时保留可读原文。摘要不替代原始完整参数。
- 展开时按实际调用顺序展示区域内每次调用的名称、完整参数、状态和完整结果，不使用分组后的顺序重排明细。JSON 参数格式化显示，无法解析时保留可读原文。
- `tool_result.result` 为 MCP content 数组；展示文本内容，非文本内容用可读的类型或结构化表示呈现，不静默丢失。`tool_error` 显示错误及其可用结果，不能视为整个任务失败。
- 所有工具调用区默认收起，结果零行预览，不再提供三行预览或 `+n lines`。每个区域使用统一展开/收起开关，不再按单次调用独立展开。收起时仍显示执行中和失败标记，错误正文及附带结果归入展开明细。
- 展开区域收到新的调用或结果时直接更新可见明细，不自动收起、不要求再次点击；收起区域收到结果仍保持收起。缩放保留各区域展开状态。
- 标题、任务输出、工具调用区、输入框、状态栏等所有文本左右各留两个终端字符；背景色仍铺满宽度。工具调用区与前后文本各隔一行空白。折行宽度、输入光标、选择复制和点击坐标统一基于该布局；极窄窗口安全退化，不出现负宽度或越界。
- 鼠标点击提示触发展开或收起，拖动用于选择文本；渲染、命中检测和复制共享一致的可见布局。终端控制字符不得作为远端控制指令执行。
- 默认跟随底部；用户上翻后暂停跟随，显示可点击的“回到底部”。历史结果展开不触发自动跟随。底部输入区与状态栏固定，整体配色和输出层次参考截图。
- 一次只允许一个活动任务；创建及订阅期间允许编辑输入但禁止再次提交。收到 `task_completed` 后解除限制。后续提交创建独立任务，不暗示服务端支持连续会话上下文；显示明确任务边界。
- `task_completed` 的 `Delta` 为 `{}`，仅表示整个任务执行和最终检查点保存成功。处理该事件后显示已完成并主动关闭连接；回放收到该事件也执行相同逻辑。
- `text`、`usage.status=completed`、子代理输出、EOF、HTTP 200 和长时间无输出均不是整体完成信号。完成通知缺失时保持未确认完成状态，不推断成功。
- 底部模型和配额沿用现有展示；本期不将 `usage` 映射为真实配额。

## 修订 — 文件读取摘要与补丁展示

### Problem Statement

同一工具调用区内，多次读取同一路径时，即使其他参数不同，重复路径也会占据摘要空间。补丁操作需要清楚展示涉及的文件名和 patch 内容，方便理解修改。

### Solution

`read_file` 的调用摘要在同一工具调用区内按文件路径去重；`apply_patch` 展示涉及的文件名，并在调用明细中展示 patch 详情。

### User Stories

1. As a 终端用户, I want 同一路径的多次读取只在摘要中出现一次, so that 我能快速识别读取过的文件。
2. As a 终端用户, I want 不同读取参数不导致重复路径, so that 摘要保持简洁。
3. As a 终端用户, I want 不同路径按首次出现顺序展示, so that 我能理解读取顺序。
4. As a 终端用户, I want 展开后仍能看到每次读取的完整参数和结果, so that 我能区分不同读取操作。
5. As a 终端用户, I want 在补丁摘要中看到涉及的文件名, so that 我能快速识别修改范围。
6. As a 终端用户, I want 展开补丁调用后看到 patch 详情, so that 我能检查具体修改。
7. As a 终端用户, I want 多文件补丁列出涉及文件, so that 不会遗漏修改范围。
8. As a 终端用户, I want 无法解析的补丁仍有可读原文, so that 信息不会丢失。

### Implementation Decisions

- 在现有工具调用区的 `read_file` 分组摘要中按路径去重，保持路径首次出现顺序；其他参数不参与去重。去重范围仅限当前工具调用区，独立区域各自展示。
- 去重仅影响摘要，不合并调用或丢弃状态、参数和结果；展开时仍按调用顺序展示每次调用。重复路径涉及运行中或失败状态时，摘要仍须保留这些状态的可见提示。
- `apply_patch` 的摘要提取 patch 涉及的文件名；调用明细保留完整 patch 内容及既有状态和结果。多文件补丁展示各文件名；解析失败时保留可读原文，不静默丢弃。
- 继续遵循现有工具调用区的折行、展开和收起规则，不改变其他工具的摘要行为。

### Testing Decisions

- 用户已确认沿用现有 TUI 公共模型边界：输入工具事件，检查渲染出的摘要及展开明细，而非断言内部实现。
- 沿用现有工具调用区测试，覆盖相同路径不同参数、不同路径顺序、独立区域、重复调用状态和完整明细，以及单文件、多文件和无法解析的 patch 展示。

- 文件路径规范化或跨工具调用区去重，以及修改实际文件读取或补丁执行行为。

- 工具名称使用浅蓝色 `#75BFFF`，命令工具名称使用绿色 `#8FCA73`；失败状态使用红色 `#F16D66`，运行中状态使用灰色，完成状态使用绿色。
- 样式在折行后应用，不改变原始文本、滚动与点击坐标或复制内容。字体和字号由终端设置控制。

## 修订 — 点击悬浮任务文本定位

- 单击顶部悬浮任务文本，跳转到该 run 的原始任务文本，并暂停自动跟随；历史 run 与相同需求文本的不同 run 均按实际所属 run 定位。
- 在鼠标释放时确认单击；拖动仍用于选择复制，不触发跳转。留白不作为点击目标。

## 修订 — 隐藏工具成功状态

- 工具调用区的收起摘要和展开明细均不展示 `[success]` / `[completed]` 成功标签，保留工具名称、参数和结果。
- 继续展示运行中、失败及其他非成功状态；仅调整展示，不改变执行状态。

## 修订 — 提交后的任务文本卡片

- 参考 `prd/suspention-task.png`：提交后的用户任务需求以 `›` 开头，使用近白文字和整行灰底 `#505050`，上下各留一行同色空白。
- 长任务文本按输出区宽度换行，保留完整需求与原有左右留白；历史 run 的需求采用相同卡片样式，run 元数据单独展示。
- 顶部悬浮仍为单行，点击定位回完整任务卡片；卡片支持文本选择复制，不把背景补齐空格作为复制内容。

## 修订 — 执行计时与完成时间

- 参考 `prd/working-timer.png` 与 `prd/suspention-task.png`：创建成功开始订阅时显示 `• Working (7s • esc to interrupt)`，每秒刷新；每次新任务重新计时。
- 收到 `task_completed` 后在该任务输出末尾保留灰色 `Worked for 3m 3s • 11:25 AM`，时间采用完成时的本地时间。
- 中断显示 `Interrupted after`，网络断开不视为完成。接入已有任务从本地接入时计时，不推测服务端历史耗时；缺少时间信息的历史快照不补造耗时。

- 运行计时行上下各留一行空白，统一从输出视口预留空间，保持点击和选择坐标一致；查看历史时由“回到底部”按钮替代计时提示，极矮窗口省略实时提示。完成记录前留一行空白，底部沿用输出区留白。
