# 05: 连接中断后的续传与去重

**What to build:** 用户在连接中断后能看到连接问题，客户端恢复订阅并从已处理位置继续输出，已有内容不会重复；完成或退出后不再重连。

**Blocked by:** 01 — 接入已有任务，显示流式文本与完成状态。

**Status:** ready-for-agent

- [x] 连接失败或中途断开显示可读状态，不将网络故障标记为任务成功或任务失败。
- [x] 自动重连采用有延迟且可取消的重试，避免紧密循环；界面编辑、滚动和退出保持响应。
- [x] 只在事件处理完成后推进续传位置；重连通过 Last-Event-ID 请求该 ID 之后的事件。
- [x] 对重复事件按 ID 去重，防止文本重复追加或工具事件重复应用；不同 ID 的相同文本不被当作重复事件删除。
- [x] 续传收到 task_completed 后显示完成并关闭连接；实时及历史完成事件采用一致语义。
- [x] 完成或退出会取消活动连接和等待中的重试；迟到的连接结果不得重新启动已经结束的订阅。
- [x] HTTP 200、EOF、usage 和长期没有新事件不代表任务已完成；无法收到完成通知时不虚构任务结果。
- [x] 用本地 HTTP/SSE 服务通过 TUI 边界验证断流、错误提示、Last-Event-ID、重复与新增事件、续传完成、取消重试及连接资源释放，不依赖真实网络或模型速度。
- [x] 运行 Go 测试与静态检查；真实 SSE 回放仅作为补充联调，记录其是否含完成事件，不把旧任务缺少完成事件判为客户端错误。

## Notes

不需要等待创建、滚动或工具展示功能；去重与续传在通用事件入口验证。恢复数据受服务端保留策略限制，本票不增加本地历史持久化或数据库回放。

## Comments

已实现可取消的指数退避重连（200ms 起，最多 3s）、模型处理后确认事件位置、Last-Event-ID 续传与按 ID 去重。消息绑定订阅身份，完成/退出取消连接及重试，旧订阅消息不会影响新任务。

本地 HTTP/SSE 测试验证断流错误、续传请求、重复 ID 与不同 ID 相同文本、续传完成关闭连接、退出取消待重试；既有回放测试改用唯一事件 ID。通过针对订阅的 `go test -race` 与 `go vet ./...`。未使用真实 SSE 回放；不推断缺少完成事件的任务结果。
