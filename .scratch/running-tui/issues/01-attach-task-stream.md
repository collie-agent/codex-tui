# 01: 接入已有任务，显示流式文本与完成状态

**What to build:** 用户通过 `--task-id` 接入已有任务，看到逐步到达的文本、连接状态和明确的整体完成状态。界面参考已确认的运行截图，底部保留输入区与现有模型、配额展示，输出自动跟随最新内容。本票建立后续任务共用的异步任务订阅边界。

**Blocked by:** None (can start immediately).

**Status:** completed

- [x] 默认连接 `http://localhost:8080`，使用用户提供的任务 ID 订阅事件，不硬编码示例任务；接入已有任务显示 ID，不伪造无法查询的原始需求。
- [x] 按 SSE 协议处理分段数据，再解析外层事件和 JSON 字符串形式的 Delta；异步网络读取不阻塞输入、渲染和退出。
- [x] `text_delta` 实时追加；对应的完整 `text` 不重复展示；无增量时完整文本正常显示，不覆盖其他响应轮次，也不因内容相同删除合法的后续响应。
- [x] 输出按终端宽度正确折行，默认显示最新内容；底部输入与状态固定，Unicode、窄屏及零尺寸窗口不导致越界。
- [x] 订阅期间仍可编辑输入但不可提交；本票不引入任务创建接口。
- [x] 只有 `task_completed` 确认整体完成；收到后显示完成并主动关闭订阅，回放完成事件也同样处理。
- [x] 普通文本、usage、EOF、HTTP 200、工具错误或长期无输出均不能推断整体成功；连接错误可见。
- [x] Ctrl+D 退出释放网络资源并恢复终端；远端控制字符不会作为终端指令执行。
- [x] 沿用 TUI 公共模型消息输入与界面输出测试边界，使用本地 HTTP/SSE 服务验证请求路径、分段解析、流式与完整文本、跨轮次响应、完成断连和退出清理。
- [x] 保留现有编辑、布局与复制回归检查，运行 Go 测试与静态检查。关键协议规则有注释；网络、输出状态与渲染职责分离，不进行无关重构。

## Notes

来源为同一功能的已确认规格及任务拆分。断线自动续传由票 05 完成，历史浏览由票 03 完成。服务端没有失败通知或状态查询；旧任务可能没有新增的完成事件。

## Implementation

- 新增 `--task-id`；默认连接 localhost:8080，不创建任务。
- SSE 订阅、响应轮次状态和输出渲染分离；异步读取，按完整 SSE 帧解析双层 JSON，支持 LF、CRLF、CR、多行 data 和注释。
- 按轮次合并 delta/full text，完整响应结束后相同文本仍保留；只有 task_completed 显示完成并关闭连接。
- 输出按终端宽度折行并跟随末尾，底部输入、模型与配额固定；远端控制字符转义。
- 本地 HTTP/SSE 测试覆盖路径、分段、多行、流式即时显示、相同后续响应、完成断连、EOF 未确认完成、输入编辑与禁止提交、控制字符、窄屏和退出清理。
- 验证：`go test ./...`、`go test -race ./...`、`go vet ./...`、`go build` 通过；PTY 冒烟确认 Ctrl+D 正常退出，恢复终端属性与备用屏幕。尚未进行人工视觉检查或真实服务器联调。
