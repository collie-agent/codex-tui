# 02: 输入创建任务并串行执行后续任务

**What to build:** 用户在输入框按 Enter 创建任务，立即看到自己的需求和随后的实时输出。任务执行期间可以准备下一条输入，整体完成后再提交独立的新任务。

**Blocked by:** 01 — 接入已有任务，显示流式文本与完成状态。

**Status:** ready-for-agent

- [x] 非空白输入按 Enter 通过 POST /tasks 创建任务，请求包含原始 input 字符串；HTTP 201 返回的 task_id 用于订阅输出。
- [x] 空白输入不发送请求；界面展示用户提交的需求与明确任务边界。
- [x] 创建期间及任务运行期间只允许一个活动任务，连续 Enter 不产生重复创建；输入仍可编辑。
- [x] 创建成功后正确保留创建期间用户新编辑的草稿，不因异步响应覆盖后续输入。
- [x] 创建错误可见且保留可重试输入；不自动重发可能已经入队的创建请求。
- [x] 收到 task_completed 后允许提交下一项任务；text、usage 或连接中断不解除活动任务限制。
- [x] 下一次提交创建独立任务，不暗示服务端保留连续对话上下文；前一任务的迟到消息不会污染新任务。
- [x] 通过 TUI 消息与本地 HTTP/SSE 服务验证创建、订阅、运行中编辑、防重复提交、失败后手动重试、完成后再次提交和任务隔离。
- [x] 运行 Go 测试与静态检查，保留已有输入编辑和订阅行为。

## Notes

测试边界已经用户确认。无需服务端 schema 变更，不实现任务取消、多任务并行或会话管理。

- 新增本地 HTTP/TUI 测试验证原始输入、创建命令、防重复、草稿、失败重试及完成后新任务；调整旧 Enter 无行为测试以符合新需求。`go test ./internal/tui -run 'TestCreate|TestInputEditing' -count=1` 与 `go vet ./...` 通过；全量集成由主代理最终确认。
