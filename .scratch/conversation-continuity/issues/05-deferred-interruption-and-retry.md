# 05: 运行开始前的中断意图与失败重试

**What to build:** 用户在任务创建中或排队中按 ESC 后，无需等待运行开始再按一次；中断意图会在运行身份可用后执行。请求失败时保留草稿、明确提示原因，并允许用户再次 ESC 手动重试。

**Blocked by:** 04 — ESC 中断运行并在原会话中继续。

**Status:** ready-for-agent

- [ ] 创建请求进行中或已入队但尚无 run_id 时，ESC 记录当前任务的中断意图，显示“等待运行开始后中断”；不发送缺少身份的请求，不宣称已取消排队任务。
- [ ] 当前任务收到有效 run_id 后立即发送已记录的中断请求；重复 ESC、重复 task_info 或一致事件回放不重复发送请求。
- [ ] 中断意图只属于本次任务；创建失败后保留既有输入恢复及手动重试行为，不携带失败提交的意图自动中断用户随后重新提交的任务。
- [ ] HTTP 202、status=accepted 与 HTTP 409、status=already_requested 显示请求已接受且等待终态，不显示已中断、不解锁下一次提交，也不重复请求。
- [ ] HTTP 409、status=terminal 显示运行已结束但终态待确认，继续等待原 SSE；不能据此推断中断状态已保存或允许再次执行。
- [ ] HTTP 404、503、网络错误及其他失败显示原因，保留草稿和已有输出，不自动重新发送；用户再次 ESC 可手动重试当前运行的中断请求。
- [ ] 服务端错误文本沿用既有终端控制字符处理；错误响应不能伪造界面终态或改变会话身份。
- [ ] 请求进行中、失败后及等待终态时都允许编辑草稿，Enter 不创建新任务；只有有效终态和会话归属校验才能解锁提交。
- [ ] 手动重试仍使用当前任务的 run_id，重复 ESC 不产生并发请求；自然完成或中断终态到达后取消待发送意图，不再对该任务发起请求。
- [ ] 使用既有 TUI 消息驱动与本地 HTTP/SSE 集成边界，验证创建中及排队中的 ESC、收到身份后的自动请求、重复信息、创建失败后的意图隔离、各响应分类、网络失败及手动重试，观察实际请求、界面与提交权限；运行相关测试和静态检查。

## Notes

依赖 04 的运行身份、中断请求、终态处理和继续链路。本票不新增排队取消接口、不做自动重试、不以 HTTP 响应代替终态。终态与 HTTP 响应乱序、跨任务迟到消息和断线回放的专项回归由 06 覆盖。
