# 03: 断线与异步事件下保持会话归属

**What to build:** 用户在断线续传、事件回放及手动重试后仍保持正确会话归属，旧任务消息不会影响当前任务，草稿和串行提交行为保持可靠。

**Blocked by:** 01 — 实例内连续任务共享会话。

**Status:** ready-for-agent

- [x] 断线续传继续使用现有事件游标和去重行为，保持已绑定会话；同一任务重复或回放的一致 task_info 不误报冲突。
- [x] 已确认归属的任务断线恢复后仍可正常完成；每次新任务重新要求自身的归属确认，不能继承上一任务的确认结果。
- [x] 前一任务的迟到 task_info、完成事件或连接消息不能确认、覆盖或解锁当前任务；迟到的冲突信息也不得污染当前任务。
- [x] 会话冲突引发的提交限制不会因重连、重复事件或完成事件被解除；不会自动切换会话。
- [x] 创建请求失败保留可重试输入，不自动重发；已绑定会话下的手动重试仍携带同一 ConvId，尚未绑定时不伪造会话 ID。
- [x] 创建中和运行中连续 Enter 不产生重复任务；创建期间编辑的新草稿不被异步响应覆盖。
- [x] 只有入队响应、没有归属或完成事件时，界面不宣称验证成功或任务成功，不自动创建替代会话。
- [x] 扩展现有 TUI 消息与本地 HTTP/SSE 的续传、创建重试和消息隔离测试，通过请求、渲染与提交行为断言以上规则，并修复暴露的问题。
- [x] 运行 Go 全量测试和静态检查，覆盖既有编辑、输出浏览和续传回归；不以私有状态或内部函数调用代替外部行为验证。
