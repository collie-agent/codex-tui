# 01: 实例内连续任务共享会话

**What to build:** 普通启动后，首个任务建立会话，后续任务自动延续该会话；用户可看到会话身份，归属缺失或冲突时得到明确提示并停止继续提交。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [x] 普通启动首次 POST /tasks 只发送原始 input，省略 ConvId；创建响应中的 task_id 继续用于订阅本次任务。
- [x] 正确二次解析 task_info 的 Delta，以非空 conv_id 绑定会话；不使用 run_id 或 task_id 代替会话 ID。
- [x] 状态栏显示绑定的会话 ID；后续请求携带字段 ConvId，值为该 ID，不误用 conv_id。修正将后续提交描述为独立新会话的文案。
- [x] 每个任务独立要求有效归属确认；仅在收到 task_completed 且本次归属验证成功后允许提交下一任务。
- [x] 首个或后续任务完成时缺少有效 task_info，显示原因并阻止后续提交；无效 JSON 或空 conv_id 不构成有效确认。
- [x] 返回会话与已绑定会话冲突时，保留原 ID、显示协议异常并阻止后续提交；完成事件不能解除限制。
- [x] 不持久化身份；普通重启开始新会话。不自动切换或创建替代会话。
- [x] 保留创建中和运行中的串行提交限制、草稿编辑、输出阅读行为；HTTP 201 不表示任务完成或归属确认。
- [x] 在绑定、逐任务确认、冲突保护等关键逻辑处解释约束，保持状态、协议解析与请求发送职责清晰。
- [x] 沿用 TUI 消息与本地 HTTP/SSE 集成边界，验证首个请求、连续两次任务、状态展示、缺失及冲突的外部行为；运行相关测试和静态检查。
