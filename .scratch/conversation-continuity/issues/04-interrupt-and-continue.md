# 04: ESC 中断运行并在原会话中继续

**What to build:** 用户在已开始的任务中按 ESC 请求中断，看到请求与终态的区别；确认中断后保留已有输出和草稿，再次按 Enter 在原会话中提交新的要求继续工作。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] 从当前任务 task_info 的第二层 JSON 保存 run_id；conv_id 仍用于会话归属，task_id 仍用于 SSE 订阅，不相互替代。
- [ ] 已取得 run_id 的运行期间，ESC 向 POST /runs/{run_id}/interrupt 发送无请求体请求；即使输入框有草稿或用户正在浏览历史输出，也优先请求中断，保留草稿和全部已有输出。
- [ ] 区分请求进行中、请求已接受且等待终态与已中断；HTTP 202 不显示“已中断”，不解锁下一次提交。请求进行中及已接受后重复 ESC 不重复发送。
- [ ] 识别原任务 SSE 的 task_interrupted（Delta 为 JSON 字符串“{}”），结束订阅并显示已中断；没有本地 ESC 请求时也能正确识别该终态。task_completed 仍按正常完成处理。
- [ ] 只有收到终态且本任务会话归属已有效确认、无冲突时才允许再次提交；缺失、无效或冲突归属仍显示原因并阻止提交，不能继承前一任务的确认。
- [ ] 终态不会自动提交草稿；用户再次 Enter 时发送新 input 和原 ConvId，不发送原 run_id，使用返回的新 task_id 订阅下一任务并继续追加输出。
- [ ] 下一任务重新等待自身 task_info，清理上一任务的运行身份、中断意图与请求状态，保留实例会话身份；不能误中断上一运行。
- [ ] 终态优先于中断 HTTP 响应；请求错误不得伪造终态或解锁提交。非成功响应的完整分类与手动重试由 05 扩展，专项竞态覆盖由 06 完成。
- [ ] 没有运行时 ESC 保留原有回到底部行为；保留 Ctrl+C 选区复制和 Ctrl+D 退出，关闭本地连接不隐式请求服务端中断。
- [ ] 更新使用说明，解释等待中断确认、再次 Enter 才继续、继续使用原会话创建新运行，以及中断不能撤销工具已经产生的操作。
- [ ] 在逐任务身份、终态确认和异步响应隔离等关键逻辑添加约束注释，保持状态、协议解析、请求发送与输出展示职责清晰。
- [ ] 沿用 TUI Update/View 与本地 HTTP/SSE 集成边界，通过实际请求、界面和提交权限验证正常链路、重复 ESC、草稿及输出保留、无本地请求的中断终态、归属缺失与冲突保护，以及下一任务的独立归属确认；运行相关测试和静态检查。

## Notes

依据“实例内会话延续、中断与继续”规格。已有会话延续能力已实现，可直接在此基础上开展，无需新增前置重构票。只使用 codex-go 已有中断接口和 task_interrupted，不修改服务端，不恢复原 ReAct 执行位置。
