# 06: 断线与异步竞态下可靠地中断和继续

**What to build:** 用户在中断请求、重试和继续过程中遇到断线、事件回放或迟到响应时，仍能看到正确状态，保持会话归属，并且不会过早或重复执行下一任务。长期没有终态时继续安全等待，保留草稿编辑和退出能力。

**Blocked by:** 04 — ESC 中断运行并在原会话中继续；05 — 运行开始前的中断意图与失败重试。

**Status:** ready-for-agent

- [ ] 中断期间沿用现有 SSE 游标、断线重连和去重机制；重连不清除中断意图、已接受请求的等待状态或持久的会话归属错误。
- [ ] 一致 task_info、答案及工具事件的回放不重复呈现输出或发送中断请求；回放中的 task_interrupted 可正确结束等待并关闭订阅。
- [ ] task_interrupted 先于中断 HTTP 成功或失败响应到达时，保持已中断与正确提交权限；迟到响应不得覆盖终态或触发重试。
- [ ] task_completed 先于中断 HTTP 成功或失败响应到达时，保持正常完成，不显示已中断，也不因迟到错误重新阻止本可进行的提交。
- [ ] 下一任务创建中或运行中收到上一任务迟到的中断 HTTP 响应、task_info、终态或连接通知时，不改变当前任务的归属、运行身份、中断状态或提交权限。
- [ ] 中断请求失败后手动重试涉及的迟到响应不能污染当前请求状态；终态到达后不再因旧错误发送额外请求。
- [ ] 会话冲突引起的提交限制不会因重连、回放、HTTP 响应或任一终态解除；缺失当前任务归属时，旧任务信息不能代替当前确认。
- [ ] 只有入队响应、请求已接受、停止输出、SSE 断开或长期没有终态时，界面不显示已中断或成功，不通过固定延时或超时解锁，不自动执行草稿，不创建并行或替代任务。
- [ ] 长期等待时仍能编辑草稿与使用 Ctrl+D 退出；本地退出和取消 HTTP/SSE 不额外请求服务端中断，不宣称服务端已经停止。
- [ ] 回归已有输出浏览、工具明细、选区复制、草稿保护、重复 Enter、无运行时 ESC 及普通和指定会话启动行为；中断后新任务仍独立确认归属。
- [ ] 扩展现有 TUI Update/View 与本地 HTTP/SSE 集成测试，以可控响应顺序、断线及回放验证上述行为，通过实际请求、界面、连接生命周期和能否再次提交断言结果，不依赖私有状态或内部调用；修复测试暴露的问题。
- [ ] 完成相关测试、Go 全量测试、竞态检测、静态检查与差异格式检查，并记录结果。

## Notes
