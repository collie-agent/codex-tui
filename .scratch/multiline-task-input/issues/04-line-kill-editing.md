# 04: Ctrl+U / Ctrl+K 删除当前显示行光标前/后的文字

**What to build:** 用户可以一键放弃当前显示行的前半段或后半段文字，立即重写；删除范围以屏幕上看到的显示行为界，不合并行、不吞掉主动换行，删除后可直接继续输入或提交。

**Blocked by:** 03 按显示行移动光标（共用显示行边界与导航分发入口）

**Status:** ready-for-agent

- [ ] 在折成多行的草稿中，于中间显示行的中部按 Ctrl+U，仅删除该行光标前的文字，前一行与该行光标后的文字保留，光标落在该行起点；对称地按 Ctrl+K，仅删除光标后的文字，光标落在该行终点。
- [ ] 光标位于软换行共享的偏移时，按当前光标归属的显示行确定删除范围，同一逻辑行其余显示行的文字保留。
- [ ] 在含 Ctrl+J 主动换行的草稿上：行尾按 Ctrl+K 不删除换行符，行首按 Ctrl+U 不与上一行合并，段落结构保持不变。
- [ ] 中文宽字符、组合字符与表情混排的草稿删除后无残缺字素，光标列宽正确。
- [ ] 空显示行按 Ctrl+U/K、光标在行首按 Ctrl+U、行尾按 Ctrl+K 均为无操作，不改变草稿与光标；连续 Ctrl+U 再 Ctrl+K 清空当前显示行且其余行不变。
- [ ] 先用 Ctrl+A / Ctrl+E 定位到显示行边界再按 Ctrl+K / Ctrl+U，可一次删除整行后半或前半。
- [ ] 删除导致显示行数减少时输入框高度收缩；删除后调整终端宽度重新排版，剩余草稿完整且光标可见。
- [ ] 删除后按 Enter 仅发出一个任务请求，捕获的正文与删除后的草稿逐字一致。
- [ ] 通过现有 TUI 模型发送含 ModCtrl 的 u/k 真实按键与尺寸消息，只断言渲染行文本、光标位置、高度与捕获的提交正文；测试在固定宽度下断言删除范围。
