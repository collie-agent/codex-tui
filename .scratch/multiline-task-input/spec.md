# 任务输入框的多行编辑

Status: ready-for-agent

## Problem Statement

编写较长的任务时，单行输入框只能显示光标附近的一段文字。用户很难对照前后文修改内容，也缺少在提交前主动分行的快捷键。

## Solution

任务输入框随文字折行而增高。用户可以按屏幕上看到的行移动光标，用 Ctrl+J 在插入点分行，用 Ctrl+U 删除当前显示行光标前的所有字符、Ctrl+K 删除光标后的所有字符，最后按 Enter 将整份草稿作为一个任务提交。

## User Stories

1. 作为任务编写者，我希望长文本到达输入区右边界时自动折行，以便连续阅读整段话。
2. 作为任务编写者，我希望输入框从一行内容开始随行数增高，以便看见刚输入的内容。
3. 作为正在查看会话的用户，我希望输入框最多占终端可用高度的一半，以便继续查看任务输出。
4. 作为长草稿的编写者，我希望达到高度上限后输入框随光标滚动，以便看见当前编辑位置。
5. 作为任务编写者，我希望删除文字或拉宽窗口后输入框自动收缩，以便让出多余空间。
6. 作为任务编写者，我希望 Ctrl+A 将光标移到当前显示行首字符之前，以便在这一行开头插入文字。
7. 作为任务编写者，我希望 Ctrl+E 将光标移到当前显示行末字符之后，以便从这里继续编辑。
8. 作为任务编写者，我希望上下方向键每次移动一个显示行，以便在同一段的不同折行之间修改文字。
9. 作为任务编写者，我希望纵向移动时记住目标屏幕列，以便越过短行后回到原列。
10. 作为中文用户，我希望光标按终端显示宽度对齐并落在完整字符边界，以便编辑中英文和表情混排的文本。
11. 作为任务编写者，我希望 Ctrl+J 在光标处分开前后两段文本，以便在草稿中组织段落和空行。
12. 作为任务编写者，我希望 Enter 一次提交整份草稿，以便服务端收到主动插入的换行及完整原文。
13. 作为任务编写者，我希望按 Ctrl+U 一次删掉当前显示行光标前的全部文字，以便快速重写这一行的开头。
14. 作为任务编写者，我希望按 Ctrl+K 一次删掉当前显示行光标后的全部文字，以便保留开头、丢弃后半段。
15. 作为任务编写者，我希望删除范围以屏幕上看到的显示行为界，以便行为与我看到的折行一致。
16. 作为长草稿的编写者，我希望 Ctrl+U 不影响前面显示行的内容，以便只重写当前这一行。
17. 作为长草稿的编写者，我希望 Ctrl+K 不影响后面显示行的内容，以便只截断当前这一行。
18. 作为多段落草稿的编写者，我希望 Ctrl+K 不会吞掉当前行末尾的主动换行，以便段落结构保持不变。
19. 作为多段落草稿的编写者，我希望 Ctrl+U 不会把当前行与上一行合并，以便 Ctrl+J 插入的分行保持原样。
20. 作为任务编写者，我希望删除后光标仍停在原来的文本位置（Ctrl+U 后位于行首，Ctrl+K 后位于行尾），以便立即继续输入。
21. 作为任务编写者，我希望在自动折行产生的软换行处按 Ctrl+U/K 只删除该显示行的部分，以便同一逻辑行的其余文字保留。
22. 作为中文用户，我希望删除按完整字符边界进行，以便不会留下半个汉字、组合字符或表情。
23. 作为任务编写者，我希望删除后输入框高度随显示行数减少而收缩，以便让出多余空间。
24. 作为任务编写者，我希望删除后调整终端宽度重新排版时草稿保持完整，以便剩余文字不因删除操作而错乱。
25. 作为任务编写者，我希望在空显示行上按 Ctrl+U 或 Ctrl+K 无任何效果，以便误按不破坏草稿。
26. 作为任务编写者，我希望光标在行首按 Ctrl+U、行尾按 Ctrl+K 时无任何效果，以便边界行为可预期。
27. 作为任务编写者，我希望连续按 Ctrl+U 再 Ctrl+K 能清空当前显示行而不波及其他行，以便快速放弃整行内容。
28. 作为任务编写者，我希望删除后按 Enter 提交的任务正文与删除后的草稿完全一致，以便服务端收到我确认过的内容。
29. 作为任务编写者，我希望先用 Ctrl+A / Ctrl+E 定位到显示行边界再配合 Ctrl+U / Ctrl+K，以便一次删除整行前半或后半。

## Implementation Decisions

- 显示行是草稿按当前输入区域宽度排版后占据的一行。自动折行只改变排版。调整终端宽度时重新排版，保留草稿及光标对应的文本位置。
- Ctrl+A/E 和上下方向键共用显示行边界。纵向移动遇到较短的行时落在其末尾，继续纵向移动到足够长的行时恢复目标列。首行向上、末行向下保持当前位置。
- 输入框根据显示行数增减高度，达到半屏上限后在框内滚动。在极小的非空终端中优先保留一个可见编辑位置。
- Ctrl+J 插入一个真实换行，光标随之移至下一行开头。Enter 沿用现有任务提交条件，提交内容直接取自草稿。
- 编辑、光标定位和渲染使用同一套终端列宽与字符边界规则。
- Ctrl+U 删除当前显示行起点到光标之间的文本；Ctrl+K 删除光标到当前显示行终点之间的文本。显示行终点不包含行末的主动换行符，因此两个快捷键都不会合并行或改变段落结构。
- Ctrl+U / Ctrl+K 与 Ctrl+A / Ctrl+E、上下方向键共用同一套显示行边界：光标位于软换行共享的字节偏移时，按当前光标归属的显示行（由行尾/纵向导航状态决定）确定删除范围。
- 删除后光标停留在原字节位置：Ctrl+U 后落在当前显示行起点，Ctrl+K 后落在当前显示行终点；纵向移动的目标列状态按普通编辑重置。删除以完整字素为操作单位，结果自然落在字符边界上。
- 按键分发上，Ctrl+U / Ctrl+K 与 Ctrl+A / Ctrl+E、上下方向键同属依赖显示行排版的输入操作，走相同的导航入口，而不是当作普通文本插入。删除后排版缓存按现有机制随草稿变化失效重算，输入框高度、框内滚动与终端光标复用既有几何逻辑，不新增布局规则。
- 空删除范围（光标已在行首/行尾或行为空）为无操作，不改变草稿与光标。

## Testing Decisions

- 采用已确认的唯一入口，即现有 TUI 模型。沿用输入编辑、窗口缩放和任务创建测试的方式，发送真实类型的按键与尺寸消息，读取视图与光标，并通过现有测试服务捕获提交请求。断言用户可见行为和请求内容。
- 输入一段会折成三行的文本，在第二个显示行分别按 Ctrl+A、Ctrl+E 后插入字符，核对插入位置。覆盖中文宽字符、组合字符和表情。
- 从长行经短行移动到另一长行，验证目标列恢复；从首末行向外移动，验证光标仍在原处。
- 从一行输入到超过高度上限，再删除文字、缩窄和拉宽终端，检查高度增减、光标可见性及草稿完整性。
- 在“你好”和“世界”之间按 Ctrl+J，验证分行和光标位置；再插入一个空行。按 Enter 后捕获一个任务请求，确认正文仅含主动输入的换行。另验纯自动折行的草稿提交后与输入原文相同。
- 行内删除测试同样发送真实类型的按键消息（含 ModCtrl 的 u/k 键），先例是本特性中 Ctrl+A / Ctrl+E 显示行边界测试与纵向导航测试的写法；只断言渲染行文本、光标位置、高度与捕获的提交正文，不断言内部数据结构。
- 在折成多行的草稿中，于中间显示行的中部按 Ctrl+U，核对仅该行光标前文字被删、前一行与该行光标后文字保留、光标位于该行起点；对称地验证 Ctrl+K。覆盖中文宽字符、组合字符与表情混排的草稿，确认删除后无残缺字素且光标列宽正确。
- 在含 Ctrl+J 主动换行的草稿上验证：行尾按 Ctrl+K 不删除换行符，行首按 Ctrl+U 不与上一行合并；随后 Enter 提交，捕获一个任务请求并核对正文与删除后的草稿一致。
- 验证空行、行首 Ctrl+U、行尾 Ctrl+K 均为无操作；连续 Ctrl+U + Ctrl+K 清空当前显示行且其余行不变。
- 删除导致显示行数减少时，验证输入框高度收缩；删除后调整终端宽度，验证剩余草稿完整且光标可见。

## Out of Scope

- 删除内容的撤销/恢复或剪切板（kill-ring）能力。
- Ctrl+W（按词删除）等其他行编辑快捷键。
- 任务历史导航、子代理只读视图的编辑能力、粘贴规则调整，以及任务提交协议变更。

## Further Notes

- 显示行会随窗口宽度改变。同一草稿在不同宽度下提交，应产生相同的任务正文。
- 同一逻辑行在不同终端宽度下折行不同，Ctrl+U / Ctrl+K 的删除范围随之不同；这是“以显示行为界”的预期行为，测试应在固定宽度下断言。
- 本特性应复用既有显示行边界与编辑入口，不引入新的排版或删除抽象（遵循 AGENTS.md 关键处加注释、避免过度设计的要求）。
