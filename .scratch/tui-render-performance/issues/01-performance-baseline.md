# 01: 建立可重复的性能基线

**What to build:** 为维护者提供可重复运行的短会话、长会话和持续流式输出测量，能够量化界面刷新、历史滚动与内存成本，为后续优化确定验收预算。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [x] 以现有 TUI 模型 Update → View 为主要测试边界，固定终端尺寸、事件序列与数据规模，在计时区外准备数据。
- [x] 场景覆盖纯文本、复杂 Markdown、中文与表情、大工具结果及工具调用区折叠和展开；比较短会话与数量级增长的长会话。
- [x] 分别测量未变化状态的重复 View、流式增量 Update 加 View、历史滚动加 View，记录 ns/op、B/op、allocs/op。
- [x] 记录 CPU、alloc_space 和 inuse_space 采样，区分临时分配、派生缓存和原始正文的驻留成本。
- [x] 给出可复现命令、环境、输入规模及多次测量结果；基于测量写明后续耗时、分配、驻留内存及短会话回退的量化预算。
- [x] 基线场景校验实际可见内容和状态，避免对空白界面或未执行的事件链进行计时；不新增仅服务测试的生产 API。


## Comments

2026-11-15：用户确认以 Model.Update → View 及同边界 benchmark 为测试边界。已完成测试夹具、三轮基准、CPU / alloc_space / inuse_space 采样和固定历史内存实验；未修改生产 API 或实施渲染优化。

结果、环境、复现命令与后续量化预算见 [基线报告](../baseline/README.md)，原始数据与采样 top 输出位于同目录。长会话折叠工具时 View 中位数约 298 ms、84.33 MiB/op；固定历史 GC 后堆约 1.8 MiB，累计分配不代表驻留。完整行为测试通过。三操作短样本是初始基线，后续收益验证需按报告扩充样本。
