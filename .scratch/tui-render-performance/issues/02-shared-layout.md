# 02: 共享布局，减少事件更新中的重复渲染

**What to build:** 用户在流式输出期间仍能顺畅阅读、滚动和复制；同一有效状态的界面布局在显示与交互之间复用，减少重复排版，同时保持现有选区失效语义。

**Blocked by:** 01 — 建立可重复的性能基线。

**Status:** ready-for-agent

- [x] 先整理布局所有权与失效边界，再让渲染、滚动范围、鼠标命中和复制共享同一有效布局结果；本票落地后可独立运行。
- [x] 移除流式事件处理前后为比较而生成完整界面文本的路径，以明确的内容及布局变化信息判断是否需要更新。
- [x] 后台输出未改变可见内容时保留有效选区；可见内容或坐标改变时沿用现有正确的选区失效行为。
- [x] 验证滚动锚点、回到底部、工具调用区点击与展开、中文及表情复制、极窄窗口和缩放行为。
- [x] 历史加载、任务与代理视图切换后布局正确；明确值传递模型中的共享可变状态所有权，避免旧模型和其他视图受污染。
- [x] 使用 01 的基线证明重复刷新或事件更新的耗时及分配改善，相关行为回归通过，并注释关键失效不变量。


## Comments

### 实现与测试（2026-11-15）

- 用户确认以 `Model.Update → Model.View` 和已有剪贴板请求为行为测试边界；性能复用 ticket 01 的固定事件 benchmark，不新增生产 API。
- TDD red：`TestToolExpansionPreservesPreviousModelView` 在原实现失败，展开新模型的工具调用区会改变旧模型的视图。green：更新前复制读取状态，隔离 responses/output、工具调用区、工具结果、代理映射和选区点击目标后通过。
- 每个读取模型持有单个可替换的输出布局，显示、滚动范围、点击和复制均复用该布局；宽度、正文、展开状态或内容事件使布局失效。元数据更新不重新排版正文。布局没有历史版本或宽度版本集合。
- 值模型更新复制可变源状态及缓存所有权，并将缓存里的工具点击目标映射到新模型；旧模型与其他代理视图不会因展开、结果更新或代理映射修改受到污染。缓存行仅供读取，呈现层不修改缓存内容。
- 移除流式事件前后为比较而生成整屏文本的路径。仅存在选区或拖动时，比较可见布局、坐标和状态栏等显示数据；后台输出未改变可见布局时保留选区。
- 回归：`go test ./internal/tui -skip '^TestStreamRefresh' -count=1` 通过，覆盖现有滚动/回到底部、工具点击与展开、中文及表情复制、窄窗口与缩放、历史与代理切换场景。独立于 ticket 04 的快照也通过新增旧模型隔离测试。

- 同命令五轮前后测量见 [ticket02/README.md](../ticket02/README.md)，原始数据保留。Long 六个组合的耗时与两项分配指标均低于同参数重测前版本的 50%，Short 六个组合无回退；最终驻留内存预算由集成验证单独记录，未把 B/op 当作存活堆。
- 主线程已完成集成 `go test ./...`、`go test -race ./...`、`go vet ./...` 和 `git diff --check`，全部通过。

- 集成驻留实验通过：固定历史两种展开状态的 GC 后堆均低于 4 MiB，5→15 次循环分别增长 800 B 和减少 67,256 B，完整源数据 109,344 B 保留。详见 [报告与原始内存记录](../ticket02/README.md)。15 次实验不替代 ticket 06 的长期验证。
